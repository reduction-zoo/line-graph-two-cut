## Maintaining the board

- One stable, descriptive filename per fixed problem; do not put search dates in filenames.
- Before adding a card, search existing endpoints, restrictions and aliases to avoid duplicates.
- Update the card's definition, evidence, next step and assessment in place. Keep a dated
  research-history entry with actual queries and coverage limits.
- Keep `status`, `openness`, `difficulty`, `importance`, `tags` and
  `last-literature-check` metadata on each card. Update the board row when its assessment changes.
- `ready-for-attempt` and `proof-route-hold` describe proof readiness; neither certifies openness.
  Move completed investigations to a separate draft/review section. Keep resolved or rejected
  cards in a closed section with the decisive evidence rather than silently deleting them.
- Record later searches in the corresponding cards. Keep useful rejected results under
  `research/closed/`; do not create per-round reports or duplicate dossiers.
- Shared probes live under `research/evidence/`. Keep new problem-specific evidence
  alongside its card when it needs several artifacts.
- Use the [question template](../question.md) for the contents of new cards and the
  [screening method](../screening-method.md) for assessments. Copy a fixed question into a
  campaign only when beginning that campaign; that snapshot is not the maintained board card.

## Shared Karp contract

For the fixed source language A and target language B of each entry, construct
one deterministic algorithm f and prove, for every finite input string x,

    x belongs to A if and only if f(x) belongs to B.

Give explicit worst-case polynomial time and output-bit-length bounds in |x|.
All well-formed source instances, including NO instances, must produce objects
satisfying the target's stated structural restrictions. Malformed source strings
may map to a designated malformed target string, which is outside B. All numeric
input data are binary encoded. Thresholds are part of the output instance. No
oracle calls, randomized runtime or approximation are allowed. Each rule also
requires deterministic polynomial-time recovery of a source witness from every
valid witness of its constructed target. Negative results are informative but do not fulfill the positive
reduction target. A different restriction requires a different question.

**ETR** is the decision language of true existential sentences over the
reals, with Boolean combinations of polynomial equalities and inequalities and
binary integer coefficients, using an explicit finite polynomial representation.
An ETR instance and the output of its reduction are finite strings. Real-valued
existential witnesses do not make the reduction a real-RAM or oracle algorithm.
The entrywise-L1 and geometric-thickness targets seek stronger hardness than the NP-hardness already known. Witness recovery is an additional repository requirement, not part of standard Karp reducibility.
